Ulexite とは

Ulexite は、VRChat の中で使う家電と端末のシリーズです。最初の製品は Android TV 風のテレビ（セットトップボックス）Ulexite TV で、ワールドに置いて、リモコンで操作します。動画の再生と同期は VizVid が受け持ち、Ulexite は「テレビを見る体験」（ホーム画面、リモコン、アプリ）を受け持ちます。

これらの製品で動く共通の仕組みを Ulexite OS と呼びます。アプリは Ulexite OS の上で動くので、1つのアプリが複数の製品・端末で動くことを目指しています。

2つの実行環境

Ulexite OS は、性質のまったく違う2つの場所で動きます。

ワールド環境コンパニオン環境
どこで動くかVRChat のワールドの中（Udon）利用者の PC（外部プログラム「Ulexite Companion」）
端末Ulexite TV、Ulexite Player（レコーダー）などアバター用のタブレット・スマホ・ウォッチ
誰の画面かワールドの全員が同じ画面を見る端末を持っている本人だけが見る
インターネット決まったサイトのファイルを読むだけ（5秒に1回）自由に通信できる（許可した相手だけ）
書く言語UdonSharp（U#）C#（.NET）
状態動いています設計中

2つの環境は直接つながりません。Udon は外の世界と通信できず、外部プログラムはワールドに触れられないためです。たとえば「タブレットで選んだ動画をワールドのテレビで流す」ことはできません。両方に同じ情報を出したいときは、共通のサーバーにデータを置いて、それぞれが読みます（ワールド側は10分ほど遅れます）。

アプリの種類

アプリの作り方は2つあります。両方を組み合わせることもできます。

データで書くアプリ（declarative）

画面を「決まった型と部品の組み合わせ」で JSON に書き、表示する値は feed（データの JSON ファイル）から読みます。プログラムは書きません。

  • 向いているもの：天気、航空気象（METAR）、運行情報、ニュース、ランキングなど「データを見る」アプリ
  • 良いところ：同じ定義が、テレビでもタブレットでも動く（予定）。安全で、審査も通りやすい。重くなりにくい
  • できないこと：ゲーム、凝った動き、自由な配置、端末の上での計算（計算はサーバーで済ませておく）

4章 データで書くアプリ

プログラムを書くアプリ（native）

画面とふるまいを、環境ごとにプログラムで書きます。

  • ワールド環境：UdonSharp（U#）で書きます。画面はエディタ上で作って焼き込みます
  • コンパニオン環境：C# で書きます。最初は公式アプリだけです（ほかの作者には段階を追って開きます）
  • 向いているもの：ゲーム、メディア再生、時計・タイマーのような手元で動くもの
  • 例：時計アプリ

プログラムを書くアプリ（native）

迷ったら、まずデータで書くアプリで作れないか考えてください。Ulexite が一番勧める形です。

層の分け方

┌───────────────────────────────┐
│ アプリ（あなたが作るもの）          │
├───────────────────────────────┤
│ シェル（ホーム画面・通知など。端末ごと）│
├───────────────────────────────┤
│ システムアプリ                      │
│  ・Ulexite App Services（アプリの窓口）│
│  ・Ulexite Media Services（再生）    │
│  ・設定・アプリストア など           │
├───────────────────────────────┤
│ Ulexite System（OS の土台）         │
└───────────────────────────────┘

アプリが使ってよいのは Ulexite App Services だけです。シェルや土台を直接呼んではいけません（ストアの審査で確かめます）。App Services には、データの読み込み、画像、通知、保存、再生、アプリ間の呼び出し、テーマの色などの窓口があります。

アプリのマニフェスト

どのアプリも、パッケージの直下に ulexite-app.json（マニフェスト）を置きます。アプリの ID・名前・バージョン・作者・種類・対応する端末・使うデータ・保存の予算などを書くファイルで、アプリ情報の画面やストアのページもここから作られます。

{
  "manifestVersion": 1,
  "id": "weather",
  "name": { "ja": "天気", "en": "Weather" },
  "version": "0.1.0",
  "publisher": { "name": "Ulexite Technologies" },
  "kind": "declarative",
  "runtimes": { "world": { "os": 1, "appServices": 2, "screens": "app.screens.json" } },
  "profiles": ["tv"],
  "data": [ { "id": "weather", "every": "10m" } ],
  "budget": { "saveKB": 1, "imagesPerOpen": 1, "syncBytes": 4 }
}

全項目はリファレンス（9章）にまとめています。

配り方

  • ワールド環境：アプリは VPM パッケージ（vrc.ulexite.app.<アプリID>）です。ワールドの制作者が Unity のアプリストア（エディタ拡張）から入れて、ワールドを上げ直すと訪問者に届きます。公開後のワールドの中で、アプリを入れ替えることはできません
  • コンパニオン環境：アプリは .ulxapp というファイルです。利用者が PC の管理画面のストアから入れます。更新はその場で届きます
  • 最初は公式アプリと、Ulexite が審査した提携アプリだけを受け付けます（8章。準備中）

開発に必要なもの（ワールド環境）

  • Unity 2022.3.22f1
  • VRChat Worlds SDK 3.10.5 以上（UdonSharp は SDK に入っています）
  • VizVid（idv.jlchntoz.vvmw）1.8.2
  • Ulexite TV（vrc.ulexite.tv）

これらをまとめて入れられる Ulexite 開発キット（vrc.ulexite.devkit）があります。VCC で1つ入れると、上の全部と、Ulexite Emulator、「新しいアプリ」ウィザード、見本のアプリ（ハローワールド・天気）、テスト用のシーン、申請の前の検査がそろいます。入れると最初に「足りないもの」の確認窓が開きます。

開発キットの VCC への配布は、Ulexite TV の公開に合わせて始めます。

用語

用語意味
端末Ulexite OS が動く1台。テレビ、レコーダー、アバターのタブレットなど
シェル端末ごとのホーム画面と画面の枠
feedアプリが読むデータの JSON。共通サーバーに置く
共通の feedどのアプリからも読める feed（地震・津波・警報など）。OS が1分おきに読んでいる
操作する人その端末のリモコンを持っている人。画面の状態のオーナー
焼き込みエディタで作ったもの（画面・URL）をワールドに固定して入れること。Udon は実行中に URL を作れないため、URL はすべて焼き込む
