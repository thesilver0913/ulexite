9.1 マニフェスト（ulexite-app.json）

アプリのパッケージの直下（package.json の隣）に置きます。version と作者は package.json が正です（VCC が読むのは package.json だけ）。テレビを作り直すときに読み、決まりに合わないところは Console にエラーで出ます（UlexiteAppManifest.Check）。

{
  "manifestVersion": 1,
  "id": "weather",
  "name": { "ja": "天気", "en": "Weather" },
  "version": "0.2.0",
  "publisher": { "name": "Ulexite Technologies", "url": "https://example.com" },
  "kind": "declarative",
  "runtimes": { "world": { "os": 1, "appServices": 4, "screens": "app.screens.json" } },
  "profiles": ["tv"],
  "permissions": [],
  "data": [],
  "settings": [],
  "budget": { "saveKB": 4, "imagesPerOpen": 1, "syncBytes": 256 },
  "releaseNotes": { "ja": "最初のバージョン", "en": "First version" },
  "icon": "Textures/icon.png",
  "category": "info"
}

トップレベル

項目型必須既定決まり・例
manifestVersionint必須—1 だけ
idstring必須—英小文字・数字・- で32文字まで（^[a-z0-9][a-z0-9-]{0,31}$）。アプリの appId と同じにします（例：weather）
nameobject必須—{ "ja": "...", "en": "..." }。両方書きます（片方でも欠けるとエラー）
versionstring必須—1.2.3 の形。package.json の version と同じにします
publisherobject必須—{ "name": "...", "url": "..." }。name は package.json の author.name（または Ulexite Technologies）と同じ
kindstring必須—native（U# で書く）か declarative（データで書く）
runtimes.worldobject必須—下の表。無いとワールドでは使えません
profilesstring[]必須—出す端末。tv・player・world-tablet・avatar-tablet・phone・watch。tv が無いとテレビに出ません
permissionsstring[]任意[]ワールドでは空にします（入れるとエラー）
preinstalledbool任意false同梱（プリインストール）のアプリか。アプリ情報のラベルが「プリインストール」になります
iconstring任意""パッケージからの相対パス（例：Textures/icon.png）
categorystring任意""アプリストアの分類（例：media・info・tools）
backgroundbool任意falseCompanion で常駐を許すか（ワールドでは使いません）

runtimes.world

項目型必須既定決まり・例
osint必須—必要な Ulexite OS（ワールド）の版。1 以上。今は 1
appServicesint任意0必要な App Services の版。今は 4 まで。足りないとアプリストアが「本体の更新が必要です」と出します
entrystringnative は必須—画面を作る UlexiteAppBuilder のクラス名（例：UlexiteClockBuilder）
screensstringdeclarative は必須—画面の定義のファイル名（例：app.screens.json）

data（読むファイル）

マニフェストの data は、URL を直接指定するデータ（時差の表など）に使います。データで書くアプリの画面のデータは、定義のファイル（9.3）の assets・data に書きます。

項目型必須既定決まり・例
idstringurl を書くとき必須—英小文字・数字・- で32文字まで。焼き込みの名前は「アプリID-データの id」
feedstring任意—共通の feed の名前を読むとき（古い形。新しいアプリは url を使います）
urlstring任意—https の信頼済みドメインだけ：*.github.io・gist.githubusercontent.com・pastebin.com・*.vrcdn.cloud・*.disbridge.com
everystring任意—読む間隔（例：10m・6h・24h）

settings（アプリの設定項目）

アプリの画面から開く共通のパネルに出ます。最大 8 件。

項目型必須既定決まり・例
idstring必須—英小文字・数字・-・_ で32文字まで。重複不可
typestring必須—choice（選択）・toggle（オン/オフ）・order（選んで並べる）・time（時刻）
scopestring必須—local（各自。PlayerData）・global（全員共通。共有データ）・creator（制作者が焼き込む。変更不可）
choicesstringchoice・order は必須—選択肢の表の名前（Packages/vrc.ulexite.tv/Data/choices/<名前>.json。例：jma-areas）
defaultstring[]任意nullchoice は1つ、order は max 以下、toggle は true/false。@region で OS の地域になる
maxint任意3order の上限。1〜10
stepint任意5time の刻み（分）。1〜60
labelstring必須—翻訳キー（例：Ulexite.Clock.Setting.Alarm）
notestring任意—補足の翻訳キー

翻訳キーの書き方：マニフェストに書く label・note はキーそのもの（t: を付けない）です。データで書くアプリの定義（9.3）では t: を付けます。

budget（予算）

項目型既定上限決まり
saveKBint416自分の保存データ（PlayerData）の割り当て。Ulexite 全体で 60KB（うちシステムが 16KB）
imagesPerOpenint0—1回開く間に読む画像の枚数の目安（ワールド全体で5秒に1枚の枠を分け合います）
syncBytesint2561024共有データ（全員に同期する小さな値）の量。標準より小さく書いても標準（256）になります

releaseNotes

{ "ja": "...", "en": "..." }。アプリ情報に出ます。

足すだけの欄（今は読みません）

項目型決まり
pricingobject有料アプリ。type は free・paid・freemium。有料なら seller（販売元）と url（購入ページ）が必須。Ulexite はお金を扱いません
licenseobject有料アプリの確かめ方。type は key（ライセンスキー）・account（販売元のアカウント）、verify は確かめる先
symbolobjectCompanion のアイコン。index（記号の番号。既定 -1）・color（テーマの色の番号）
crossMenuobjectUlexite Player の Cross Menu。categories（string[]）・items

9.2 App Services（services）

アプリは launcher ではなく services（App Services） を通して Ulexite TV の仕組みを使います。UlexiteApp の services フィールドに、ランチャーが Start で入れます（アプリ側で探す必要はありません）。

  • 戻り値のある窓口は、その場で値が返ります
  • 結果を待つもの（データ・画像・確認・文字入力）は、アプリのイベントに届きます（9.2.14）
  • アプリへの知らせは 1フレーム遅れて届きます（アプリで例外が出ても窓口とランチャーが止まらないように）

必要なものだけ書けばよいです（書かなければ何も起きません）。

_OnServicesFeed()自分のデータが届いた／状態が変わった
_OnServicesCommonFeed()共通の feed が届いた
_OnServicesStorageReady()保存データが読めるようになった

_OnServicesSharedChanged()共有データが変わった

9.2.15 呼ぶ順と気をつけること

  1. _Init で feed を登録（_RegisterFeed／_RegisterDataFeed）。開いたときに読み直すのは _OnOpen で _ReloadFeed
  2. 保存は StorageReady が true になってから。_Save* が false を返すときは、まだ読めていないか、ID の形が違います
  3. 確認と文字入力は「操作する人」だけ。false が返ったら開けていません（操作していない人から呼ばれた）
  4. 答えはイベントで受ける。_Confirm の戻り値は「開けたか」だけで、はい／いいえは DialogAccepted
  5. 通知の id はアプリの中で一意に。同じ id で書き換えます。消すときは _RemoveNotify
  6. _OpenApp の動作と引数は同期しません（開くことだけ全員にそろう）。開いたアプリが結果を自分で同期してください
  7. Udon の制約：List は使えません（配列か DataList）。例外が出た UdonBehaviour はそのセッション止まるので、重い処理は分けます（3章）

scale:<名前>{{ 31 | scale:temp }}temp は色の名前（下記）。それ以外は muted
